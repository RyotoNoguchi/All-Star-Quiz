# 複数端末・同時回答の検証

## 実行

Node 22、PostgreSQL 17、Redis 7.4を起動し、`.env` の `TEST_DATABASE_URL` と `TEST_REDIS_URL` をローカルまたはCIのテスト用サービスへ設定する。

```sh
npm ci
npx playwright install chromium
npm run check
npm run test:e2e
```

LinuxのCIでは `npx playwright install --with-deps chromium` を使用する。CIは通常のチェックに続けてE2Eを実行し、失敗時はスクリーンショット・トレースを7日保持する。

E2Eは本番ビルドを作り、ポート3200（Web）と3201（通信）で起動する。これらのポートが使用中なら既存プロセスを止めず失敗する。`.next` を再生成するため、同じ作業ディレクトリのプレビューは停止してから実行する。通常のプレビューに戻すときは通常の環境変数で `npm run build` を実行する。

毎回ランダムな `quiz_e2e_…` スキーマと専用Redisプレフィックス、短命な署名鍵を作る。固定問題2件だけを投入し、実際のHTTP・WebSocket・DBを使う。通常の公開スキーマや他のRedisキーを消さない。終了時は起動したプロセスを停止し、その回のスキーマとRedisキーを削除する。同時実行を防ぐ `.e2e-running` は通常終了・失敗・割り込み時に除去する。強制終了やマシン停止で残った場合は、対象プロセスが終了したことを確認してからロックを除去し、残存する `quiz_e2e_…` だけを管理上片付ける。

## 検証範囲

- 独立したCookie・ストレージを持つChromiumの複数コンテキストで、作成→参加→準備→出題→回答→脱落→復帰→優勝→本人履歴まで操作する。
- 390×844の参加画面と1920×1080のモニターで横幅のはみ出しを検査する。選択肢や履歴への移動をキーボードで操作し、見出し・ラベル・状態通知をアクセシビリティ向けの役割で検査する。
- ホスト退出後の操作権限移譲、未参加者の履歴表示、他人の履歴URLを検証する。
- 2部屋それぞれ20人を独立HTTPセッションで同時参加・回答させ、部屋ごとの20回答、優勝、履歴、別部屋の参照拒否と再送の同一受付を検証する。実測時間をログに出す。40人の画面描画性能や実ネットワークの遅延を保証するベンチマークではない。
- 全員不正解・全員未回答は実時間の締切で優勝者なしになることを確認する。
- 厳密な同着は時刻を制御するDB結合テスト `final.integration.test.ts`、締切直前受付・再送は `answers.integration.test.ts`、切断猶予とホスト移譲は `game-flow.integration.test.ts` と `realtime.integration.test.ts` で再現する。E2Eと合わせて `npm run check` を必須とする。

ブラウザーを分離する方法は [Playwright公式のコンテキスト分離](https://playwright.dev/docs/browser-contexts) に沿う。OSの読み上げソフトそのものによる読み上げ品質や実機Safariは、この自動検証の対象外。
