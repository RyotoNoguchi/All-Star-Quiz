# 個人履歴の保存と参照

ゲーム終了時に、ゲーム結果・参加者ごとの履歴・終了イベントを同じ PostgreSQL トランザクションで保存する。履歴はゲームとユーザーの組で一意。保存に失敗すると終了処理全体が取り消され、再試行で一度だけ保存される。プロセス再起動後も DB から取得できる。導入前の終了済みゲームはマイグレーションで既存順位から補完する。

保存項目は参加時の名前、終了日時・理由、優勝の有無、順位、生存問題数、脱落した問題と理由。脱落問題番号は1始まり（開始前は0、脱落なしはnull）。ルームの有効期限が切れても履歴は残る。ゲームやユーザーを管理上削除すると関連履歴も削除される。

`history.list` は本人の履歴を新しい順にページ取得し、セッション期限を返す。`history.detail` は本人のゲームだけを参照でき、他人の履歴と存在しない履歴は同じエラーになる。ユーザーIDをリクエストで指定する機能はない。詳細は自分が参加していた問題のうち結果公開済みのものと、自分の回答のみを返す。中断された未公開問題や他人の回答・識別子は返さない。

本人の識別には30日有効の HttpOnly ゲスト Cookie を使用する。期限切れ・Cookie削除後は以前の履歴にアクセスできず、現在はアカウントへの紐付けや復旧機能はない。DBの履歴が消えたという意味ではない。localStorage に保存できるのは最後に閲覧したゲームIDのみで、認証情報や成績を保存しない。localStorage の消去は閲覧位置を消すだけで、CookieやDB履歴には影響しない。ストレージが利用できなくても履歴APIは利用できる。

画面と統計の表示は Issue #25 で追加する。

検証では終了トランザクション失敗と再試行、二重終了、別DBクライアントでの再取得、既存データ補完、本人限定参照、セッション失効、未公開問題の除外、優勝・同順位・誤答・時間切れ・最遅脱落と回答詳細を確認する。
