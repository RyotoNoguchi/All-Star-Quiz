# ゲスト認証（ADR-005）

名前だけで参加できる体験を維持するため、参加者の認証はサーバー生成の256-bitランダムトークンによる不透明なDBセッションを採用する。OAuthのアカウント登録は要求しない。NextAuthのユーザー名／パスワード方式へ名前だけを渡して認証を代用することもしない。管理者認証は #7 で別途実装する。

User.idは安定した本人ID、GuestSessionは期限付きアクセス手段、Participant.idは各ルーム内の参加者ID。APIはCookieからUser.idを解決し、body内のuserId／playerIdで本人を指定させない。部屋への所属は別に検証する。

- Cookie名は `quiz-participant`。HttpOnly、SameSite=Lax、HTTPS時Secure、Path=/、30日の絶対有効期限。操作ごとに期限を延長しない。
- DBはトークンのSHA-256ハッシュのみ保存。未登録・形式不正・期限切れは認証しない。GET／退出は401、作成／参加は新しいゲストとして開始できる。
- 旧DBのtokenHashは最初のアクセス時にGuestSessionへ一度だけ移行し、旧ハッシュを消す。旧Cookieの有効期限は元の1日を維持する。失効したセッションを旧ハッシュから復活させない。
- 同じブラウザーのタブは同じ本人。同じルームの再参加は同じParticipantを返す。別ルームには別のParticipantを作り、ルームからの退出はその部屋だけに作用する。
- 別タブの退出は次の状態取得で反映。再読み込みはCookieが有効なら同じ参加者を復元する。
- Cookieを消去した場合や期限切れ後に、名前だけで以前の本人として復元することはできない。別の名前で参加し直す。ルームの期限は24時間で、通常のセッションより短い。
- 作成／参加の最初の通信でセッションを発行する。同一ブラウザーでCookie発行前に複数タブから同時に初回参加しない。発行後のタブ共有は検証済み。
- 変更APIはOrigin完全一致も検証する。別ドメインのリアルタイム接続にはこのCookieを転送せず、#10で短命チケットを使用する。

テストは `npm run test:db`。Cookie属性、期限切れ、失効、旧Cookieの移行、複数タブ相当の再参加、複数ルーム、他人ID指定と別Originの拒否を実DB＋Route Handlerで確認する。
