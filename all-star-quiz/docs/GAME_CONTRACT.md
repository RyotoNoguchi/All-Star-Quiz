# サバイバルクイズ仕様 v1

Issue #1の確定仕様。要件・設計・型定義の正本。現在は契約のみで、対戦処理の実装は #11〜#18 に委ねる。

## 基本ルール

- 2〜20人で開始。ホストも参加者に含む。開始後の新規参加は不可。既存参加者は復帰可能。
- 全問題の制限時間は10秒。開始前に問題セットを固定し、最後の1問だけを最終問題とする。通常問題だけのセットや空セットでは開始不可。
- 開始時に全員を生存中にする。通常問題では不正解・未回答を脱落させ、正解者が2人以上なら最遅の1人も脱落させる。
- 正解者が1人なら最遅による脱落はない。生存者1人になっても自動優勝せず次問へ進む。全員脱落なら優勝者なしで終了する。
- 最終問題では最速正解者1人が優勝。不正解・未回答は脱落し、他の正解者は生存のまま非優勝。正解者なしなら優勝者なしで終了。
- 同一ミリ秒の正解は、サーバーが原子的に付与する受付連番の小さい方を早い回答とする。通常問題は連番の最大の1人が脱落、最終問題は最小の1人が優勝。氏名・参加順・抽選で決めない。受付連番と時刻はルーム内で単調に確定させ、時計の逆行で過去の回答より早くならないようにする。
- 最終問題であることは事前通知しない。締切後の結果発表時に鐘を鳴らして明かす。出題開始時には鳴らさない。
- 生存問題数は、参加中に判定を通過し生存していた問題の数（最終問題の正解者も加算）。未出題なら0。平均回答時間は有効回答だけを対象にし、0件なら0ms。
- v1は生存と優勝で競う。得点加算は行わず既存のscoreは0。順位は優勝者→最終問題の他の生存者→後の問題まで生存した脱落者。非優勝の同じ到達問題の参加者は同順位とし、表示順だけ参加順とする。

## 時刻・受付・再送

- 開始時刻と締切は権威を持つサーバーの整数Unixミリ秒。`deadlineAt = startedAt + 10000`。複数プロセスではルームの単一順序で原子的に処理し、クライアント時刻を判定に使用しない。
- 有効な受付区間は `startedAt <= receivedAt < deadlineAt`。9999msは受理、10000msは拒否。受信時刻は認証済みコマンドがサーバーのルーム受付に入った時刻で、DB書込完了時刻ではない。
- 回答はセッション本人の最初の有効な1件のみ。開始前、締切後、別問題、脱落済み、退出済み、不正選択肢は拒否。回答時間は `receivedAt - startedAt`。
- 締切処理と回答処理は同じ直列化境界を使う。締切前に受付済みのコマンドを反映してから結果を確定する。全生存者の回答がそろえば10秒未満でも締め切る。
- `requestId` はクライアント生成のUUID。セッション本人・ゲーム・問題・requestIdを冪等キーとする。同じキー・同じ内容の再送には保存済みの受付結果を返す（締切後も返す）。同じキーで内容変更は `REQUEST_CONFLICT`、別キーの二度目の回答は `ALREADY_ANSWERED`。ゲーム保存期間中は受付結果を保持する。
- 通信遅延の補正や自己申告時刻による救済はしない。画面タイマーは参考表示。受理時の確認応答は本人だけに送る。

## 状態遷移と許可操作

| 現在 | 操作・条件 | 次 | 実行者 |
|---|---|---|---|
| waiting | 名前参加・退出・問題セット選択 | waiting | 本人／セット選択はホスト |
| waiting | 2人以上・有効セットで開始 | playing | ホスト |
| playing | 最初の有効な回答 | playing | 生存参加者本人 |
| playing | 全生存者が回答、または締切到達 | closing | サーバーのみ |
| closing | 受付済み回答の確定・脱落／優勝判定 | results | サーバーのみ |
| results | 通常問題・生存者あり、次問へ | playing | ホスト |
| results | 最終問題または生存者0人 | finished | サーバーのみ（結果通知後） |
| waiting / playing / closing / results | 中止 | finished | ホスト |
| 任意の未終了状態 | 明示的退出 | 同じ状態（下記例外） | 本人 |
| finished | 閲覧・履歴取得 | finished | 権限を持つ閲覧者 |

- 不正な状態の操作は `INVALID_PHASE`、権限なしは `FORBIDDEN`。開始／次問／中止にもrequestIdと期待versionを必須とし、二重操作は同じ結果を返し古いversionは `STALE_VERSION`。
- closing中は新しい回答も次問も受け付けない。判定は一度だけ永続化。中止と判定が競合したら先に確定した順に処理し、終了後の処理を無効にする。
- 中止・全員退出・期限切れは優勝者なし。finishedは終端状態で、再開催は新しいゲームを作る。
- resultsからfinishedへ自動遷移しても最終の問題結果をsnapshotに保持する。演出終了をサーバーの進行条件にしない。

## 退出・切断

- waitingの退出は現在の実装どおり名簿から除去。ゲーム開始後は記録を残し、明示退出した生存者を `left` 理由で脱落させる。復帰しても回答権は戻らない。
- 一時切断だけでは脱落・退出扱いにしない。締切までに未回答ならtimeout。締切前の復帰では残り時間内に回答できる。
- 問題中に回答済みで退出した人は正解者の速度比較から除く。全生存者の回答がそろったかを再評価し、必要ならclosingへ進む。退出と締切判定はサーバーの確定順で扱い、確定済み結果は改変しない。
- ホスト明示退出時は未退出者の参加順で権限を引き継ぐ（脱落者も司会は可能）。ホストが切断状態で30秒経過したら、接続中の未退出者の参加順で引き継ぐ。候補なしなら保留し、復帰時に再評価。元ホスト復帰で権限を巻き戻さない。
- 未退出者が0人なら終了理由 `all_left`。生存者のみが0人なら結果を発表して `all_eliminated`。作成24時間後は未終了ゲームを `expired` で終了し、新規操作を拒否する。結果の保存期間は #24・#27 で決める。

## 通信契約

`src/types/game.ts` の内部GameStateと、公開GameSnapshotは別物。内部Question（正解・最終フラグ含む）やAnswerを結果発表前にそのまま配信しない。`src/lib/game-contract.ts` の公開用変換を通す。型への代入だけでは余分なプロパティは除去されない。

- 公開出題はid・問題文・4択・カテゴリだけ。正解、解説、type、未出題問題、問題総数は結果前に出さない。
- 各イベントにはgameId、eventId、version（部屋内で単調増加する整数）、serverTimeを付与。初回／復帰時は `STATE_SYNC` でsnapshotを取得する。
- 同じversionの重複は無視、versionが飛んだ場合は再同期。1回の公開状態更新に1つのversionとイベントを割り当てる（複数種のイベントが必要なら別versionにする）。本人限定の確認応答では公開versionを進めない。新しいsnapshot取得中に届いた古いイベントで状態を戻さない。
- 出題は `QUESTION_STARTED`、参加・退出・ホスト変更は `STATE_SYNC`、締切は `QUESTION_CLOSED`。出題中は `ANSWER_COUNT_UPDATED` で人数のみを全体配信する。
- `ANSWER_ACCEPTED` は本人限定の確認応答（requestId・選択肢・受付時刻・回答時間）。正誤は含めない。本人用回答情報は専用のPrivateGameSnapshotに限る。
- `QUESTION_ENDED` で初めて正解・解説・最終フラグ・各人の回答と時間・脱落理由・生存状態を公開する。鐘はこの結果のisFinalから一度だけ再生する。復帰snapshotでは過去の鐘を再生しない。
- `GAME_ENDED` は終了理由、優勝者（いる場合）、同順位を表せる順位、最終問題結果を持つ。中止／全員退出／期限切れは未発表の正解を公開しない。
- すべての読取・送信でセッションの所属を確認する。playerIdの指定で本人を偽装できない。ホスト操作もサーバー認可必須。モニター用権限の発行は #7・#19 で実装する。

## 後続Issue用の判定例

時間は開始からのms、括弧内は受付連番。記載の回答は正解とする。

| ケース | 入力 | 期待結果 |
|---|---|---|
| 通常・速度差 | A=1000(1), B=2000(2), C不正解, D未回答 | B slowest、C wrong、D timeout、A生存 |
| 通常・正解1人 | A=1000(1), B不正解 | A生存、次問へ。まだ優勝しない |
| 通常・正解0人 | A不正解, B未回答 | 全員脱落、優勝者なし |
| 通常・同着 | A=1000(1), B=1000(2), C=1000(3) | Cだけslowest、A/B生存 |
| 最終・同着 | A=1000(1), B=1000(2) | A優勝、Bは生存・非優勝 |
| 最終・正解0人 | A未回答, B不正解 | 優勝者なし |
| 最終・正解1人 | A=9999(1), B未回答 | A優勝、B timeout |
| 締切境界 | A=9999、B=10000 | A受理、B ANSWER_CLOSED。Bは未回答扱い |
| 開始前 | receivedAt < startedAt | INVALID_PHASE、受付記録なし |
| 再送 | 同キー・同選択肢を締切後に再送 | 初回の確認応答。人数・時刻を変更しない |
| 回答変更 | 同キーで別選択肢／別キーで再回答 | REQUEST_CONFLICT／ALREADY_ANSWERED |
| 回答済み退出 | A=1000(1), B=2000(2)、Aが判定前に退出 | A left、Bは唯一の正解者として生存 |
| 切断 | A切断し未回答、B回答済み | 締切でA timeout、B生存 |
| 全員退出 | 未退出参加者が0人 | finished、all_left、優勝者なし |
| 中止 | ホストがplayingで中止 | finished、cancelled、正解は非公開 |

#11は状態遷移、#12は受付境界・再送、#13は通常判定、#14は最終判定、#15・#16は秘匿と再同期、#26は上記全ケースを実装・検証する。
