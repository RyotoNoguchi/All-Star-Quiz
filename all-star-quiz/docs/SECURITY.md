# 依存パッケージと本番の防御

Issue #27でNext.js 15.5.25、React 19.1.9、Prisma 6.19.3、sharp 0.35.4、Vitest 4.1.11へ更新し、依存関係の修正を反映した。`npm run security:check` をCIで必須にする。監査結果は実行時点の登録済みアドバイザリに対するもので、未知の問題がないことを保証するものではない。

`overrides` でPostCSS 8.5.28、picomatch 2.3.2、deepmerge-ts 8.0.2を指定する。Prisma 6の設定ツールが固定するdeepmerge-ts 7系には修正がないため、設定の読み込み・コード生成・migration・全DBテストを確認して8系を使用する。Prismaが修正版を採用したらoverrideを再評価する。直接依存のmajor更新を一括強制しない。

本番はHTTPS Origin、PostgreSQLのTLS/証明書検証、認証付きRedis TLS、ランダムな署名鍵、利用頻度制限を起動時に確認する。CSPの通信先は同一Originと設定された通信サーバーだけにし、本番でunsafe-evalを許可しない。Next.jsの初期化スクリプトのためunsafe-inlineは残る。

認証済みAPIがアクセス境界。Supabaseのブラウザー向けAPIにアプリのテーブルを公開しないためRLSを有効にする。サーバーはテーブル所有者として接続し、セッション・所属・ホスト・管理者の権限確認を引き続き行う。非所有者のDBロールから行を取得できないことを結合テストで検証する。

ログに資格情報・回答内容・表示名を出さない。秘密情報を含むバックアップやE2E以外の本番トレースは公開リポジトリへ保存しない。鍵の更新はWebと通信の同時反映を計画し、既存チケット失効後にクライアントを再接続させる。
